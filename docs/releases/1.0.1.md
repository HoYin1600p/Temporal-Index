# Temporal Index 1.0.1 — Wolds Comparability Pass

Temporal Index 1.0.1 makes its lightweight temporal-relic handling compose safely with Wold's Vaults while keeping Wold's entirely optional.

## What changed

- Replaced the competing `TemporalShardItem.getState` implementation with a cancellable injection at lower mixin priority.
- Allowed modern Wold's Vaults builds to remain authoritative for their temporal state, identification, restrictions, and loot behavior.
- Retained Temporal Index's compact `identified` marker for relics stored inside the book.
- Kept the runtime dependency limited to Vault Hunters; the release contains no Wold's imports or class references.

## Wold's Vaults validation

- **Wold's Vaults 0.33.1 / Vault 3.21.6.6884:** passed a full survival-mode client test. Activating a shard from the Index reduced the shard stack from 5 to 4, and the generated identified Daycare relic was routed into reserved slot 15.
- **Wold's Vaults 0.32.3 / Vault 3.21.5.6573:** passed client startup with both temporal-shard mixins applied and no overwrite conflict or mixin application error.
- **Wold's Vaults standalone 0.23.4 / Vault 3.21.62:** passed the Vault API compile check. This older build does not patch `TemporalShardItem` and therefore has no temporal-method collision.

The complete source also compiled successfully against all four distinct Vault Hunters JARs represented by the CMA instances, including CMA Remastered.

## Requirements

- Minecraft 1.18.2
- Forge 40.3.11 or a compatible Forge 40.x build
- Java 17
- A compatible Vault Hunters `the_vault` build
- Temporal Index installed on both client and server

Wold's Vaults is optional. When used, install matching Wold's and Temporal Index versions on both client and server as required by the pack.

## Installation

Place `temporal_index-1.0.1.jar` in the `mods` directory for the client and server. Back up worlds before installing or updating any mod.
