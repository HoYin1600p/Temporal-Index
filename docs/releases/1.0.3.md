# Temporal Index 1.0.3 - Canonical Temporal Relic Data

Temporal Index 1.0.3 standardizes identified Temporal Relics as they enter the Index so equivalent relics obtained from different generation paths can share their reserved slot.

## Highlights

- Keeps only the Vault-compatible `identified`, `modifier`, and `duration` tags on identified relics accepted by the Index.
- Discards generation-source metadata, serialized Vault Gear data, client caches, custom names, and unrelated third-party tags.
- Canonicalizes relics before manual and shift-click merge comparisons.
- Covers automatic pickup, shard-generated relic routing, partial insertion remainders, and direct item-handler insertion.
- Reconstructs extracted relics using the same clean representation, so sanitized data remains after removal from the Index.
- Preserves positive Vault-provided durations and uses the existing 6,000-tick fallback when no valid duration is present.

## Compatibility and safety

- The sanitizer accepts only identified Temporal Relics whose modifier matches one of the Index's 16 reserved variants.
- Unidentified Temporal Shards retain their separate slot and behavior.
- The implementation is original and has no code or runtime dependency on Wold's Vaults.
- Vault Hunters remains authoritative for shard loot generation, modifier identity, duration, relic effects, restrictions, and consumption.
- Temporal Index remains required on both the client and server.

## Requirements

- Minecraft 1.18.2
- Forge 40.3.11 or a compatible Forge 40.x build
- Java 17
- A compatible Vault Hunters `the_vault` build

## Installation

Place `temporal_index-1.0.3.jar` in the `mods` directory on both the client and server. Remove older Temporal Index JARs and back up worlds before updating.
